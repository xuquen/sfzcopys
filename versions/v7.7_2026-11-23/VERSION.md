# v7.7 @ 2026-11-23

## 修复：去阴影之后白平衡失效、色偏残留（作者反馈「去阴影之后白平衡开关没有任何效果了 且而色偏」）

**根因**：v7.5 的管线是 `原图 → 去阴影 → 白平衡`。平场校正把阴影区按约 1.6 倍提亮时，
三通道一起 clip 到 255，**色偏信息在那一步就丢了**；之后再估亮部灰世界，白底像素全被
堆到同一亮度，估出的增益被稀释到 ≈1（实测 `[1.016,0.992,0.992]`），开关等于摆设。

**修法**：管线反转成 `原图 → 白平衡 → 去阴影 → 白底增强`——色偏在 clip 之前先被校正。
增益仍在原图上估（wbGain 输入 c.cv），作用到 c.cv，缓存键 `wbFor===c.cv`。
曾试过「相对纸白选点在平场后图上估」，更差：平场后处处 ≈255，选点失去区分力。已放弃。

**实测**（2 张真实手机直出）：
- #2 偏蓝卡 R/B 0.806 → **0.971**（修复前同组合 0.895）；#1 偏暖 1.061 → 0.986
- 增益恢复区分力：`[1.11,0.993,0.916]`
- 四种开关组合重绘 0 报错；旋转 180° 作废全部派生缓存（1729~1731）

**缓存失效点**：`#ckSh` 只作废 sh/hc（白平衡在它上游，不受影响）；`#ckWb` 作废 wb/sh/hc；
rot 作废全部。`wbGain` 顺手抽出独立函数，`applyGain` 增益≈1 时返回 null 省一份内存。

## 新增：「粘贴」按钮改名「微信图」

作者问「从微信聊天读取文件好不好做」。结论：网页读不了微信聊天记录本身（无 API、
跨 App 隔离），唯一通用通道是**剪贴板**——微信里复制图片 → 页面读取。本来就有
`#btnPaste` + document paste 监听，只差可发现性：
- 按钮文案「粘贴」→「微信图」，加 title 说明操作路径
- 两处 toast 改成微信语境指引（空剪贴板 / 无权限）
- 实测：真图进剪贴板 → 点按钮 → 卡数 1→2；空白灰块被「几乎没内容」门控正确拒绝

**端上能力差异**（写给以后的自己）：桌面微信右键复制 → Ctrl+V 完全可行；
手机微信内置浏览器 `clipboard.read()` 基本不可用，paste 事件安卓部分可行，
iOS 只能走相册——所以手机端主路径仍是「相册」按钮。
