## 作者需求

「手机端要拍照上传」。v6 只有一个「添加照片」（`input[type=file]` 无 capture），
手机上点开只能进相册。改成拍照为第一入口。

## 改动

### 1. 拍照按钮（主路径）

```html
<input type="file" id="cam" accept="image/*" capture="environment" hidden>
```
- `capture="environment"` → iOS/Android 直接拉起系统相机，桌面浏览器忽略该属性、退化为选文件
- 用系统相机而不是页面内 `getUserMedia` 取景：原生相机有 HDR / 多帧合成 / 全分辨率，
  拍出来的卡面文字才够清楚。页面内抓帧通常只有 720p~1080p，卡面裁出来放大到 1011×638 会糊
- 按钮顺序改为 **拍照（主色）/ 相册 / 粘贴**；「添加照片」→「相册」
- 满 2 张后再点拍照，直接 toast 拦住，不进相机

### 2. 卡面统一转正 `autoUpright()`（这次的核心 bug 修复）

v4~v6 里 `processFile` 对竖版卡是**无条件** `rotN(cv,1)`（顺时针 90°），
即假设「所有竖拍的卡都朝同一个方向倒」。实测手机直出 12 张里就有 1 张方向相反，
转完仍然侧躺；v6 静默收下这张坏图。

现在改成 `autoUpright()`：
- 竖版 638×1011 → 两个 90° 方向各转一次，各自算 `segScore`，大的留下
- 横版 1011×638 → 判 180° 倒置（`d < -12` 才转）
- `segScore = scanSegs(底部 y 0.78~0.99) - scanSegs(顶部 y 0.01~0.22)`：
  正立时底部是 18 位号码 / 签发机关两行，横向切出 20~40 段；顶部只有标题或姓名行

实测分布（手机直出 12 张 + 拼接成品切出的 20 张）：

| | segScore |
|---|---|
| 人像面正立 | +18 ~ +31 |
| 人像面倒置 | −24 ~ −28 |
| 国徽面正立 | +3 ~ +16 |
| 银行卡/社保卡 | 未测（会被 cardKind 折叠，转了也无所谓） |

阈值 **12**：`d < -12` 才转 180°，`|d| ≤ 12` 记 `unsure`、不转，卡片行显示
「方向没判准，是倒的就点 ↻」。宁可漏转，也不要把好图转坏。

**国徽面的 d 只有 +3~+16，倒置时 −3~−16，会漏掉一部分倒置的国徽面** ——
这是已知局限，靠手动 ↻ 兜底。试过用「国徽红色像素重心」补，实测 10 张国徽面
红色像素占比全是 0（国徽偏暗紫，过不了 `r>g*1.4 && r>b*1.4`），此路不通。

### 3. `wholeCard` 的 `is_vertical` 修正

整图即卡分支原来硬编码 `is_vertical:false`，导致「竖构图 + 卡竖满整个画面」的图
（手机凑近拍，1132×1800，比例 0.629 正好是 1/1.585）被 warp 成 1011×638 横向拉伸，
再无条件转 90° —— 双重错误。改成 `is_vertical: H > W`。

### 4. 卡片行加「↻ 转 180°」

方向判据宁可漏转，就得给用户补的机会。点一下转 180°、重算缩略图、重判面别。
`.ic` 是行内小按钮的公共样式，`.rot` / `.del` 只做各自的 active 配色
（踩过坑：给 rot 复用 `.del` class 会让 `querySelector(".del")` 命中 rot 按钮）。

## 实测

手机视口 390×844，走 `#cam` 上传：

| 样本 | 结果 |
|---|---|
| 12 张手机直出（含 3 张 180° 倒置、1 张侧躺） | 12/12 正立、面别全对 |
| 20 张拼接成品切出的单面卡（整图即卡） | 20/20 不误转，面别人像/国徽全对 |

`unsure` 只在国徽面（d 3~16）上出现，属预期。

## 拍摄提示

首屏 `.tip` 加了一条：「卡放平、占满画面、避开反光，正反两面各一张」。
卡占画面越满、像素越多，裁出来的 1011×638 越实。

## 顺手修的版面 bug

桌面端 `.paper` 原来只有 `max-width:470px`，1280×900 下 A4 高 665px，
页面刚好不滚动，底部 `.tip` 被固定操作栏永久压住。改成
`max-width:min(470px, calc((100svh - 285px) * 210 / 297))`，`.quickbar` 与 `.tip`
用同一个表达式保证同宽同轴。1280×900 / 1440×780 / 1024×700 三种视口实测
`tipBottom < footerTop`（余量 16px）。tip 文案同时压缩了一版，否则窄预览下换行太多。
