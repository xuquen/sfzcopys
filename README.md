# sfzcopys · 身份证打印前处理

把手机随手拍的身份证照片，自动**找框 → 矫正 → 裁切 → 摆正 → 拼进 A4**，
输出可直接打印的复印件。纯浏览器运行，**照片不出本机**。

> 中国第二代居民身份证卡面固定 85.6 × 54 mm（ISO 7810 ID-1 / CR80，≈1.585），
> 圆角半径 3.18 mm。所有几何判据都围绕这个比例建立。

---

## 做什么

| 步骤 | 说明 |
|---|---|
| **找框** | 画面里有桌面、手指、阴影、别的卡片，也能定位到卡的四角 |
| **矫正** | 单应变换把透视变形拉回正矩形，不是简单外接框 |
| **裁切** | 输出 `1011×638`，即 300 dpi 下 85.6×54 mm，**原像素**，不重采样 |
| **摆正** | 侧躺 90° 自动转正；同框有银行卡/社保卡时拆开并自动让位 |
| **拼版** | 人像面在上、国徽面在下，关于页心中线对称，间隔 10 mm，整页 A4 |
| **导出** | PDF / 高清 JPEG / 直接打印，均为 1:1 原大 |

手机端优先：竖屏单列、大按钮。导入入口四条路：**拍照**（`capture="environment"` 调系统相机）、
**相册**多选、桌面端**扫描**（扫描仪无法网页直连，走扫描件文件）、**微信图**（微信里复制图片 → 剪贴板；
网页无权直接读微信聊天，那是小程序专属 API）。另支持拖放与 `Ctrl+V`。

---

## 为什么自己造这个轮子

身份证拼版软件不少，多数要么塞一堆依赖包、要么要装客户端。这个项目的取舍只有六条：

1. **体积小** —— 只依赖浏览器，不内置一堆依赖包；唯一的「轮廓包」（角点检测模型）仅 1.9 MB，用不用都行。
2. **不挑设备** —— 手机拍照、电脑复制粘贴（截图 / 扫描件）同一条流程。
3. **电脑微信零落盘** —— 电脑端微信截图进剪贴板后，从导入到导出全程在浏览器里完成，不用找地方建本地过程文件。
4. **OCR 命名（默认关）** —— 识别只上传字段碎片小图，服务器看不到全图。
5. **手机微信导入（规划中）** —— 网页无权读微信聊天，小程序接口被卡；这条路在找办法，暂时靠电脑端微信。
6. **识别失败怎么办** —— 先提高素材质量：正对拍摄、光线均匀、避免反光，多数识别失败是图的问题不是工具的问题。

## 照片增强管线（v7.5+，可关）

四级像素链 `原图 → 白平衡 → 去阴影 → 高对比度`，前两级默认开：

| 级 | 算法 | 备注 |
|---|---|---|
| 白平衡 | 亮部灰世界（亮度 P80 以上像素估增益，±20% 限幅） | **必须在平场之前**：平场会把色偏 clip 掉，之后再估只能得 gain≈1 |
| 去阴影 | 平场校正 `out = I × 255/W`，W 为局部纸白（L6 近似滑动最大值） | 三通道同增益不改色相；均匀扫描件 gain≈1 自动跳过 |
| 高对比度 | 局部纸白归一化 + 硬阈值漂白 + 人像保护（版式先验抠人像本体） | 底纹推纯白、人像零改动；默认关 |

开关在页面「选项」区，参数（水印文字）与文件名系统在顶栏齿轮的设置弹层里。

### 保存文件名与联网 OCR（v7.10+，可选）

- 文件名模板：`{姓名}{证号}{有效期止}{地址}{时间}{固定文字}{序号}` 任意组合，默认 `身份证-{时间}`；
  序号按「新人像面 +1」计数，起始号可设。相邻标签没写分隔符会**自动补 `-`**（v7.14）。
- 联网 OCR（OCR.space 通用识别）**默认关**，开启需 confirm；**只上传模板里用到字段的裁剪小条图**
  （实测 5~20 KB，整卡 150 KB+），人像照片与整卡不出本机。Key 只存浏览器 localStorage。
- 申请免费 Key（每月 25,000 次，约 1 分钟）：**[OCR.space Key 申请教程](docs/ocr-space-key.md)**。
  服务商用 OCR.space（网页可直连）；百度接口无跨域许可，浏览器直连必被拦，已放弃。

## 两种检测引擎

默认 ML，ML 失手自动回退经典。

### ML 引擎（推荐）

`ml/doccornernet_lean.ort`（1.9 MB），ONNX Runtime Web 跑在 WASM 上。
输入 `224×224` RGB，输出四角归一化坐标 + 置信度。

两段式：

1. **整图推理** → 若宽高比不像卡（`|ln(AR/1.585)| > 0.06`），按「整宽 × 55% / 62% 高」三档滑窗再推；
2. 候选过卡形门控 + IoU 去重 → 每个候选外扩 7% 再推一次精修，只接受"更像卡"的结果。

第二步是拆同框多卡的关键：**单文档模型遇到两张同尺寸矩形时，倾向输出跨两张的并集，
而且置信度照样 1.000** —— 分数识别不出这个错误，只能靠几何门控兜住。

### 经典引擎（零依赖兜底）

纯 JS 几何启发式，不需要任何模型：灰度百分位掩膜 + 低饱和高亮掩膜 → 连通域 →
凸包 → 最小外接矩形 → 按 1.585 生成候选 → 多维打分 → 收边。

## 实测成绩

20 张自建基准，对人工标注 gold 算 IoU：

| 引擎 | IoU ≥ 0.9 | 平均 IoU |
|---|---|---|
| **ML + 整图即卡** | **20 / 20** | **0.957** |
| ML（无整图规则） | 18 / 20 | 0.928 |
| 经典引擎 | 10 / 20 | 0.826 |

另一批更硬的样本（10 人 × 2 面，每张还躺着另一张银行卡，4 张整体转了 90°）：
20 个文件拆出 26 张卡，全部框正，比例偏差 ≤ 0.015，4 张侧躺全部转正。

A4 拼版实测：整页 `2480×3508`（300 dpi），卡面 `1011×638` px = `85.6×54.02` mm，
间隙 9.99 mm，左右留白 735/734 px，上下各 1057 px —— 几何完全对称。
PDF 的 MediaBox 为 `595.28 × 841.89 pt = 210.0 × 297.0 mm`。

## 几条不显眼但关键的判据

- **指标一律用像素坐标算，算完才归一化**。反过来算，非正方形图上面积/比例直接错。
- **不做无脑内收（tighten）**。卡内文字/花纹的梯度比卡边还强，一内收就咬掉卡边：
  20/20 会掉到 15/20。功能保留但默认关闭。
- **空白卡面判据**（灰度 `std < 12`）：模型对任何图都会给四个角，纯色/渐变图上
  它照样"自信"地框一个。实测真实卡面 std 31.7~52.4、干扰图 0~4.6，中间空档极大。
- **银行卡两条判据**（满版高饱和 > 0.30、左侧人像暗像素 > 0.15）：只折叠不删除，
  误判可一键救回。工银社保卡和身份证一样白底，别的判据分不开。
- **大图先降到 ≤1800px** 再送模型，否则 WASM 侧内存吃不住。

## 已知限制

- **卡边 2~3px 脏点/暗边**：warp 采样在卡边界会采到卡外背景，高对比度模式下更显眼
  （修法＝warp 后四边 2px 边缘克隆，未做）。
- 面别判据在退化图上仍以象限墨迹为主，极端光照下可能「待定」。
- 两面配对按拍摄顺序 / 面别判据；跨正反面把姓名与有效期拼进同一文件名时，
  OCR 结果按「先到先得」合并，同一人连拍正反面即配对。
- 少数民族双语身份证未经样本验证（文字内容判据一律不用，只依赖几何/字号）。
